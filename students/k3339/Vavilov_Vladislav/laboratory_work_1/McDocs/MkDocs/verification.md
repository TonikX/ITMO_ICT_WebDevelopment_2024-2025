## Сценарии для защиты

### 1. Как различить UDP и TCP?

В первом задании используется `SOCK_DGRAM` и методы `sendto()`/`recvfrom()` — без соединения. Во втором применяется `SOCK_STREAM`: сервер вызывает `listen()`/`accept()`, а клиент — `connect()`. TCP передаёт поток байтов надёжно и в правильном порядке; UDP работает с независимыми датаграммами, не обеспечивая таких гарантий самостоятельно.

### 2. Почему HTTP-сервер использует TCP?

HTTP — протокол прикладного уровня. В этой лабораторной HTTP/1.1-запрос и ответ передаются по TCP-соединению; программа сама записывает статус `200 OK`, заголовки и тело ответа.

### 3. Как чат обслуживает несколько клиентов?

На каждое подключение создаётся поток. Доступ к словарю клиентов координируется `threading.Lock`, а функция `broadcast()` отправляет сообщение остальным участникам.

### 4. Что происходит при отправке оценки?

Браузер отправляет `POST /` с данными формы. Сервер читает длину тела по `Content-Length`, разбирает данные, проверяет оценку от 1 до 5, меняет словарь и возвращает `303 See Other` с `Location: /`. Браузер затем делает `GET /`.

### 5. Что будет после перезапуска сервера журнала?

Оценки исчезнут: в коде они находятся в словаре Python в оперативной памяти, база данных и файловое сохранение не используются.

## Дополнительная проверка HTTP

При работающем сервере задания 5 выполните:

```bash
curl -i http://127.0.0.1:8081/
curl -i -d "subject=Physics&grade=4" http://127.0.0.1:8081/
curl -s http://127.0.0.1:8081/ | grep Physics
curl -i http://127.0.0.1:8081/unknown
```

Ожидаемые статусы последовательно: **200**, **303**, затем отображение `Physics` в таблице, затем **404** для неизвестного пути.

!!! note "Доказательность"
    Все приложенные изображения относятся к выполнению первой лабораторной. Результат теста с `curl` можно воспроизвести во время защиты; он не представлен как уже зафиксированный на скриншоте.
