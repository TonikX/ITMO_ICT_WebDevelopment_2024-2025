# Аналитический отчет проекта Distribution Management System

## Введение

Настоящий отчет представляет собой комплексный анализ разработанного приложения для управления распределением периодических изданий через сеть типографий и пунктов доставки. Система реализована с использованием актуальных веб-технологий и демонстрирует практическое применение архитектурных паттернов REST API и одностраничного веб-приложения.

## 1. Краткое описание системы

### 1.1 Назначение и область применения

Приложение ориентировано на решение задач связанных с организацией и отслеживанием процесса распределения печатных изданий. Система позволяет производить управление базой данных типографий, каталогом газет и журналов, реестром почтовых отделений и деталями о распределении тиражей. Основная задача системы заключается в централизованном хранении и оперативном предоставлении информации о размещении печатной продукции у разных производителей и конечных пункты приёма.

### 1.2 Ключевые компоненты функционала

Система предоставляет следующий набор функций:

- **Управление базой периодичных изданий** — создание, редактирование записей о газетах и журналах, включая информацию об издателях и ценовой политике
- **Администрирование сети типографических предприятий** — ведение справочника типографий, отслеживание их операционного статуса
- **Регистрация пунктов распределения** — ведение реестра почтовых отделений как конечных точек доставки
- **Учет объемов выпуска** — фиксирование размеров тиражей для каждого издания в каждой типографии
- **Анализ цепочки доставки** — отслеживание перемещения печатной продукции от типографий до почтовых отделений
- **Аналитические запросы** — выполнение сложных поисковых и информационных запросов
- **Механизм аутентификации и авторизации** — контроль доступа к функциям cистемы через систему пользовательских профилей и токен-аутентификацию
- **REST API интерфейс** — предоставление стандартизированного программного интерфейса для взаимодействия с системой

## 4. Модель данных

### 4.1 Сущность "Периодическое издание"

Сущность отвечает за хранение информации о газетах и журналах.

**Атрибуты:**
- `title` — наименование печатного издания (обязательное поле, текст до 200 символов)
- `publication_index` — почтовый индекс издания (уникальное отличительное поле, текст до 20 символов)
- `editor_first_name` — личное имя главного редактора (текст до 100 символов)
- `editor_last_name` — фамилия главного редактора (текст до 100 символов)
- `editor_middle_name` — отчество главного редактора (опциональное поле, текст до 100 символов)
- `price_per_copy` — розничная цена выпуска (десятичное число)

**Дополнительная функциональность:**
- Вычисляемое свойство `editor_full_name` формирует полное имя редактора комбинируя доступные компоненты
- Записи упорядочиваются по названию по умолчанию

### 4.2 Сущность "Типография"

Представляет учреждения, осуществляющие функции печати.

**Атрибуты:**
- `name` — официальное наименование учреждения (текст до 200 символов)
- `address` — почтовый адрес расположения (неограниченный текст)
- `is_active` — признак операционной деятельности (логический флаг, по умолчанию активна)

**Особенности:**
- В строковом представлении отображается наименование и текущий статус

### 4.3 Сущность "Пункт доставки"

Представляет сеть поступления и обработки печатной продукции.

**Атрибуты:**
- `number` — уникальный идентификационный код (текст до 20 символов, уникален)
- `address` — физический адрес расположения (неограниченный текст)

**Организация:**
- Отсортированы по номеру в порядке возрастания по умолчанию

### 4.4 Сущность "Выпуск тиража"

Промежуточная сущность, устанавливающая отношение между периодическим изданием и типографией, фиксируя объем производства.

**Атрибуты:**
- `printing_house` — ссылка на учреждение печати (внешний ключ)
- `newspaper` — ссылка на периодическое издание (внешний ключ)
- `circulation` — объем одного выпуска в единицах (целое число)

**Ограничения:**
- Комбинация издания и типографии должна быть уникальной
- Отсортированы по объему выпуска в убывающем порядке

### 4.5 Сущность "Распределение"

Отражает конкретное распределение тиража от типографии к конечному пункту.

**Атрибуты:**
- `post_office` — ссылка на пункт доставки (внешний ключ)
- `newspaper` — ссылка на периодическое издание (внешний ключ)
- `printing_house` — ссылка на типографию-отправителя (внешний ключ)
- `quantity` — количество единиц в конкретном распределении (целое число)

**Особенности:**
- Тройной уникальный индекс обеспечивает идентификацию каждого маршрута доставки
- Упорядочены по пункту доставки и названию издания

## 5. Программный интерфейс (API)

### 5.1 Общие сведения

REST API предоставляет полный набор операций для работы с сущностями системы. Все эндпоинты, кроме операций регистрации и входа, требуют предоставления валидного токена аутентификации.

**Аутентификация:**
```
Authorization: Token <ваш_токен>
```

### 5.2 Управление изданиями

**Получение списка:**
```
GET /api/newspapers/
```

**Получение одного издания:**
```
GET /api/newspapers/{id}/
```

**Создание издания:**
```
POST /api/newspapers/
```

**Обновление издания:**
```
PATCH /api/newspapers/{id}/
PUT /api/newspapers/{id}/
```

**Удаление издания:**
```
DELETE /api/newspapers/{id}/
```

**Специализированные операции:**

*Поиск по названию:*
```
GET /api/newspapers/by_name/?name=<название>
```
Возвращает информацию о типографиях, где печатается издание с указанным наименованием

*Справочная информация:*
```
GET /api/newspapers/info/?id=<id> или /api/newspapers/info/?name=<название>
```
Предоставляет краткие сведения об опубликованном индексе и розничной цене

*Полная информация с вложениями:*
```
GET /api/newspapers/{id}/full_detail/
```
Возвращает детальные сведения о выпусках и распределениях издания

### 5.3 Управление типографиями

**CRUD операции:**
```
GET /api/printing-houses/           # Список
GET /api/printing-houses/{id}/      # По ID
POST /api/printing-houses/          # Создание
PATCH /api/printing-houses/{id}/    # Обновление
DELETE /api/printing-houses/{id}/   # Удаление
```

**Специализированные операции:**

*Главное издание типографии:*
```
GET /api/printing-houses/{id}/largest_circulation_editor/
```
Информирует о редакторе издания, печатаемого в типографии наибольшим тиражом

*Полные сведения с отношениями:*
```
GET /api/printing-houses/{id}/full_detail/
```
Дает полное представление о типографии со всеми выпусками

### 5.4 Управление почтовыми отделениями

```
GET /api/post-offices/
GET /api/post-offices/{id}/
POST /api/post-offices/
PATCH /api/post-offices/{id}/
DELETE /api/post-offices/{id}/
```

*Детальная информация с распределениями:*
```
GET /api/post-offices/{id}/full_detail/
```

### 5.5 Управление распределениями

```
GET /api/distributions/
GET /api/distributions/{id}/
POST /api/distributions/
PATCH /api/distributions/{id}/
DELETE /api/distributions/{id}/
```

### 5.6 Аутентификация

**Регистрация нового пользователя:**
```http
POST /api/auth/register/
Content-Type: application/json

{
  "username": "user123",
  "password": "securepassword",
  "password_retype": "securepassword"
}
```

**Вход в систему:**
```http
POST /api/auth/login/
Content-Type: application/json

{
  "username": "user123",
  "password": "securepassword"
}
```

**Ответ:**
```json
{
  "auth_token": "abc123token...",
  "user_id": 1,
  "username": "user123"
}
```

## 6. Компоненты клиентского приложения

### 6.1 Слой сервиса API

Модуль `api.ts` служит промежуточным уровнем для всех коммуникаций между фронтенд-приложением и бэкенд-сервером.

**Функции:**
- Инициализирует Axios с базовым URL на http://localhost:8000
- Автоматически включает токен аутентификации в заголовки всех запросов (перехватчик запросов)
- Обрабатывает ошибки аутентификации, перенаправляя на страницу входа при 401 (перехватчик ответов)
- Предоставляет методы для всех CRUD операций с сущностями
- Обеспечивает методы для операций аутентификации (login, register)

### 6.2 Хранилище состояния аутентификации

Хранилище Pinia `auth.ts` отвечает за управление состоянием пользователя.

**Управляемое состояние:**
- `user` — информация о текущем пользователе (id, username)
- `token` — JWT токен сохраняемый в localStorage
- `loading` — флаг процесса загрузки
- `error` — сообщение об ошибке если таковая имела место

**Методы:**
- `init()` — инициализирует пользователя при загрузке приложения
- `login()` — выполняет аутентификацию
- `register()` — осуществляет создание учетной записи
- `logout()` — удаляет токен и информацию о пользователе

### 6.3 Маршрутизация

Конфигурация маршрутов в `router/index.ts` определяет навигацию приложения.

**Защищенные маршруты (require auth):**
- `/` — главная страница
- `/profile` — профиль пользователя
- `/newspapers` — каталог изданий
- `/printing-houses` — справочник типографий
- `/post-offices` — перечень почтовых отделений
- `/distributions` — информация о распределении

**Публичные маршруты (only guests):**
- `/login` — страница входа
- `/register` — страница регистрации

**Навигационная логика:**
- Перенаправляет неавторизованных пользователей на страницу входа
- Перенаправляет авторизованных гостей на главную страницу
- Проверяет статус аутентификации перед навигацией

### 6.4 Интерфейсные компоненты

**Система навигации:**
- Боковое меню навигации с пунктами доступа ко всем функциям
- Адаптивный дизайн для различных размеров экрана

**Страница входа (LoginView.vue):**
- Форма для предоставления учетных данных
- Обработка ошибок аутентификации
- Ссылка на страницу регистрации

**Страница регистрации (RegisterView.vue):**
- Форма для создания нового аккаунта
- Проверка совпадения паролей
- Валидация входных данных

**Управление профилем (ProfileView.vue):**
- Просмотр информации о текущем пользователе
- Возможность обновления учетных данных
- Функция смены пароля

**Каталог изданий (NewspapersView.vue):**
- Таблица со списком всех газет
- Функции для создания, редактирования и удаления
- Поиск и фильтрация по названию или индексу

**Справочник типографий (PrintingHousesView.vue):**
- Отображение полного списка печатных производств
- Управление информацией о адресе и статусе
- Фильтрация по активности

**Справочник почтовых отделений (PostOfficesView.vue):**
- Каталог всех пунктов доставки
- Просмотр и редактирование адресов
- Поиск по номеру отделения

**Информация о распределении (DistributionsView.vue):**
- Таблица с информацией о всех маршрутах доставки
- Фильтрация по издаиям, типографиям и отделениям
- Управление количеством поставки

## 9. Особенности технической реализации

### 9.1 Отношения в модели данных

Система использует промежуточные модели для реализации отношений many-to-many:

- **PrintingRun** — служит связующим элементом между Newspaper и PrintingHouse, дополнительно сохраняя информацию о тираже
- **Distribution** — устанавливает трехстороннее соответствие между PostOffice, Newspaper и PrintingHouse с количественной информацией о распределении

Такой подход позволяет:
- Хранить дополнительные атрибуты для каждого соответствия
- Предотвращать дублирование данных
- Обеспечивать целостность информации на уровне База данных

### 9.2 Безопасность

- **Аутентификация:** Токен-базированная система с использованием Django REST Framework Token Authentication
- **Авторизация:** Все эндпоинты (кроме регистрации и входа) требуют авторизации
- **cross-origin requests:** Включена поддержка CORS для разных хостов (настраивается в зависимости от окружения)
- **CSRF protection:** Встроенная защита от CSRF атак в Django

### 9.3 Производительность

- **Кэширование запросов:** Использование `prefetch_related()` и `select_related()` для оптимизации количества запросов к БД
- **Сериализация:** Вложенные сериализаторы позволяют в одном запросе получить связанные коллекции объектов
- **RESTful дизайн:** Правильная организация эндпоинтов облегчает реализацию кэширования на стороне клиента
