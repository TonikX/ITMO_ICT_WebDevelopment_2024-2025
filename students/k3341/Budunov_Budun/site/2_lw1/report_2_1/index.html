    Отчет по лабораторной работе 1: Реализация серверного приложения FastAPI

    Введение

    В рамках данной лабораторной работы было разработано серверное приложение для управления задачами (Task Manager) с использованием фреймворка FastAPI. Приложение реализует полноценную систему управления задачами с категориями, тегами и расписаниями, а также включает функционал пользователей с авторизацией и аутентификацией.

    Модель данных

    Разработанная модель данных включает 7 таблиц:

    • User – пользователи системы
    • Task – задачи
    • Category – категории задач
    • Tag – теги для задач
    • TaskTag – ассоциативная таблица для связи задач и тегов
    • Schedule – расписания
    • ScheduleTask – ассоциативная таблица для связи расписаний и задач

    Связи в модели данных:

    One-to-Many:

    • User → Task (один пользователь может иметь много задач)
    • User → Schedule (один пользователь может иметь много расписаний)
    • Category → Task (одна категория может содержать много задач)

    Many-to-Many:

    • Task ↔ Tag (через ассоциативную таблицу TaskTag)
    • Task ↔ Schedule (через ассоциативную таблицу ScheduleTask)

    Ассоциативные сущности с дополнительными полями:

    • TaskTag – содержит поле added_at (время добавления тега к задаче)
    • ScheduleTask – содержит поля planned_start (планируемое время начала) и planned_duration (планируемая продолжительность)

    Реализация

    Структура проекта

    Проект имеет четкую файловую структуру:

    • main.py – основной файл с API-эндпоинтами
    • models.py – модели данных SQLModel
    • schemas.py – Pydantic-схемы для валидации данных
    • security.py – функции для работы с безопасностью (JWT, хеширование паролей)
    • functions.py – вспомогательные функции
    • database.py – настройка подключения к базе данных
    • migrations/ – директория с миграциями Alembic
    • .env – файл с переменными окружения

    Технологии и библиотеки

    • FastAPI – основной фреймворк для API
    • SQLModel – ORM для работы с базой данных
    • PostgreSQL – СУБД
    • Alembic – система миграций
    • Pydantic – валидация данных и создание схем
    • python-jose – работа с JWT-токенами
    • passlib – хеширование паролей
    • python-dotenv – работа с переменными окружения

    Функционал пользователя

    Реализован полный функционал пользователя:

    Регистрация и авторизация:

    • Эндпоинт /users/ – регистрация
    • Эндпоинт /token – авторизация и получение JWT-токена

    Безопасность:

    • Хеширование паролей с использованием библиотеки passlib
    • Генерация JWT-токенов с использованием библиотеки python-jose
    • Аутентификация по JWT-токену через зависимость get_current_active_user

    Дополнительные API-методы:

    • /users/me/ – получение информации о текущем пользователе
    • /users/ – получение списка всех пользователей
    • /users/me/change-password/ – смена пароля
    • /users/most-active – получение наиболее активных пользователей (с наибольшим количеством задач)

    API-эндпоинты

    Реализованы CRUD-операции для всех сущностей:

    Пользователи (Users):

    • Создание, чтение, обновление пользователей
    • Смена пароля
    • Получение информации о текущем пользователе

    Задачи (Tasks):

    • Создание, чтение, обновление, удаление задач
    • Фильтрация задач по различным параметрам
    • Специальные действия: начало задачи, завершение задачи, получение времени выполнения
    • Получение просроченных задач

    Категории (Categories):

    • Создание, обновление, чтение категорий

    Теги (Tags):

    • Создание, обновление, чтение тегов

    Расписания (Schedules):

    • Создание, чтение расписаний
    • Добавление задач в расписание
    • Получение расписаний пользователя с фильтрацией по датам

    Система миграций

    Настроена система миграций с использованием Alembic:

    • Файл alembic.ini содержит базовую конфигурацию
    • Файл migrations/env.py настраивает подключение к базе данных из переменных окружения
    • Миграции автоматически генерируются на основе моделей SQLModel

    Типизация данных

    Все API-методы имеют аннотации типов для входных и выходных данных:

    • Используются Pydantic-модели из schemas.py
    • Определены отдельные схемы для создания, чтения и обновления сущностей
    • Реализованы вложенные модели для отображения связей many-to-many и one-to-many

    Переменные окружения

    Используются переменные окружения для хранения конфиденциальной информации:

    • DATABASE_URL – строка подключения к базе данных
    • SECRET_KEY – секретный ключ для JWT-токенов
    • ALGORITHM – алгоритм для JWT-токенов
    • ACCESS_TOKEN_EXPIRE_MINUTES – время жизни токена

    Проброс URL в alembic.ini:

    Для этого в файле envv.py необходимо добавить следующий код: 

    from dotenv import load_dotenv
import os
load_dotenv()
# Формируем URL подключения из переменных окружения
url = os.getenv("DATABASE_URL")

# Переопределяем URL в конфигурации
config.set_main_option("sqlalchemy.url", url)

    Заключение

    Разработанное приложение полностью соответствует требованиям лабораторной работы:

    • Реализована модель данных с более чем 5 таблицами и различными типами связей
    • Ассоциативные сущности содержат дополнительные поля, характеризующие связи
    • Настроена система миграций с Alembic
    • Реализован полный функционал пользователя с авторизацией и аутентификацией
    • API-методы имеют аннотации типов
    • Код структурирован и разделен на логические компоненты

    Приложение предоставляет полноценный API для управления задачами, категориями, тегами и расписаниями с учетом пользовательских прав доступа.
