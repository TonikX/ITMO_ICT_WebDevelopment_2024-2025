    Отчет по лабораторной работе №2: Сравнение подходов параллельного программированию в Python

    Введение

    Целью данной лабораторной работы является исследование и сравнение трех различных подходов к организации параллельного выполнения кода в Python: multiprocessing, threading и asyncio.

    Для анализа были реализованы две типовые задачи: 1. CPU-bound задача: вычисление суммы чисел от 1 до 1,000,000,000. Эта задача интенсивно использует процессор. 2. I/O-bound задача: парсинг 20 веб-страниц с использованием API. Эта задача большую часть времени ожидает ответа от сети.

    На основе этих задач мы сравним эффективность каждого подхода и проанализируем полученные результаты времени выполнения.

    Описание программ и используемых подходов

    1. task_multiprocessing.py

    Данная программа использует модуль multiprocessing для выполнения задач в нескольких процессах.

    Подход и особенности: * Принцип работы: multiprocessing обходит ограничение глобального интерпретатора (GIL) путем создания отдельных процессов, каждый со своим собственным интерпретатором Python и пространством памяти. Это позволяет достичь настоящего параллелизма на многоядерных системах. * Реализация task_1 (CPU-bound): Диапазон чисел делится на части, и каждая часть обрабатывается в отдельном процессе с помощью multiprocessing.Pool. Это идеальный сценарий для multiprocessing, так как вычисления могут выполняться параллельно на разных ядрах CPU. * Реализация task_2 (I/O-bound): Список URL-адресов делится между несколькими процессами. Каждый процесс последовательно обрабатывает свою часть URL. Хотя это и работает, создание процессов является ресурсоемкой операцией (по памяти и времени), что может делать этот подход менее эффективным для I/O-задач по сравнению с threading или asyncio.

    Ключевые фрагменты кода:

    Для CPU-bound задач используется Pool, который автоматически распределяет работу между процессами и собирает результаты.

    def task_1():
    # ...
    # Создание пула процессов и выполнение задач
    with multiprocessing.Pool(processes=num_processes) as pool:
        results = pool.starmap(calculate_sum, args)

    # Суммирование результатов
    total_sum = sum(results)
    # ...

    Для I/O-bound задач процессы создаются и управляются вручную. 

    def task_2(tag_name):
    # ...
    # Создаем и запускаем процессы
    processes = []
    for i in range(num_processes):
        process = multiprocessing.Process(target=worker, args=(url_chunks[i], tag_name,))
        processes.append(process)
        process.start()

    # Ожидаем завершения всех процессов
    for process in processes:
        process.join()
    # ...

    2. task_threading.py

    Программа использует модуль threading для выполнения задач в нескольких потоках в рамках одного процесса.

    Подход и особенности: * Принцип работы: Потоки выполняются в одном процессе и разделяют общее пространство памяти. В CPython из-за наличия GIL (Global Interpreter Lock) только один поток может исполнять Python-байт-код в один момент времени. Однако GIL освобождается во время операций ввода-вывода (I/O), что позволяет другим потокам выполняться, пока один из них ждет ответа от сети или диска. * Реализация task_1 (CPU-bound): Задача по суммированию чисел выполняется в нескольких потоках. Из-за GIL потоки не могут выполняться параллельно на разных ядрах. Более того, накладные расходы на переключение контекста между потоками делают итоговое время выполнения даже больше, чем у однопоточной версии. * Реализация task_2 (I/O-bound): Каждый поток обрабатывает свою часть URL. Пока один поток ждет ответа от сервера (операция I/O), GIL освобождается, и другой поток может отправить свой запрос. Это обеспечивает эффективное конкурентное выполнение и значительно ускоряет общую обработку.

    Ключевые фрагменты кода:

    Для CPU-bound задач потоки создаются вручную, а результаты суммируются в основном потоке. 

    def task_1():
    # ...
    # Создание и запуск потоков
    threads = []
    for i in range(num_threads):
        start = i * chunk_size + 1
        end = (i + 1) * chunk_size if i < num_threads - 1 else 1_000_000_000
        thread = threading.Thread(target=calculate_sum, args=(start, end, results, i))
        threads.append(thread)
        thread.start()

    # Ожидание завершения всех потоков
    for thread in threads:
        thread.join()

    # Суммирование результатов
    total_sum = sum(results.values())
    # ...

    3. task_async.py

    Программа использует библиотеку asyncio для асинхронного выполнения кода на основе событийного цикла (event loop).

    Подход и особенности: * Принцип работы: asyncio использует кооперативную многозадачность. Задачи (tasks) явно передают управление обратно в событийный цикл, когда встречают операцию ожидания (например, await). Это происходит в рамках одного потока, что исключает накладные расходы на переключение контекста на уровне ОС и делает asyncio очень эффективным для задач с большим количеством операций ввода-вывода. * Реализация task_1 (CPU-bound): Синхронная, блокирующая функция calculate_sum не может быть просто вызвана с await. Чтобы не блокировать весь событийный цикл, она запускается в отдельном пуле потоков с помощью loop.run_in_executor. По сути, это гибрид асинхронного подхода с многопоточностью, и он также упирается в GIL, показывая схожую с threading производительность. * Реализация task_2 (I/O-bound): Для обработки блокирующих сетевых запросов также используется run_in_executor. Это позволяет асинхронной программе эффективно обрабатывать множество запросов одновременно. asyncio.gather запускает все задачи конкурентно и ждет их завершения. Этот подход имеет минимальные накладные расходы и является наиболее предпочтительным для I/O-bound задач.

    Ключевые фрагменты кода:

    Для обеих задач используется loop.run_in_executor для запуска синхронного (блокирующего) кода в отдельном потоке, чтобы не останавливать событийный цикл. asyncio.gather используется для конкурентного выполнения всех созданных задач. 

    async def run_calculate_sum(start, end):
    """Запускает синхронную функцию calculate_sum в отдельном потоке"""
    loop = asyncio.get_running_loop()
    with ThreadPoolExecutor() as pool:
        return await loop.run_in_executor(pool, calculate_sum, start, end)

async def task_1():
    # ...
    # Создание задач
    tasks = []
    for i in range(num_tasks):
        start = i * chunk_size + 1
        end = (i + 1) * chunk_size if i < num_tasks - 1 else 1_000_000_000
        tasks.append(run_calculate_sum(start, end))

    # Запуск задач и ожидание результатов
    results = await asyncio.gather(*tasks)
    # ...

    Аналогичный подход применяется для I/O-bound задачи. 

    async def task_2(tag_name):
    # ...
    # Создаем список задач для асинхронного выполнения
    tasks = []
    for url in urls:
        # Используем run_in_executor для запуска синхронной функции parse_and_save
        task = asyncio.create_task(run_in_executor(url, tag_name))
        tasks.append(task)

    # Ожидаем завершения всех задач
    results = await asyncio.gather(*tasks)
    # ...

    Анализ и сравнение результатов

    CPU-bound задача

    Как и ожидалось, multiprocessing показал наилучший результат (2.97 с). Это единственный из трех подходов, который обеспечивает истинный параллелизм, распределяя вычисления по всем доступным ядрам процессора и обходя ограничение GIL.

    Подходы threading (16.11 с) и asyncio (15.54 с) оказались значительно медленнее. В обоих случаях из-за GIL вычисления не могут выполняться параллельно. Более того, накладные расходы на создание потоков и переключение контекста между ними приводят к тому, что производительность оказывается хуже, чем была бы у простого последовательного выполнения в одном потоке. Схожее время у threading и asyncio объясняется тем, что в реализации asyncio для этой задачи использовался ThreadPoolExecutor, который по своей сути является многопоточным исполнителем.

    Вывод: для задач, интенсивно использующих CPU, multiprocessing является безальтернативным выбором для достижения максимальной производительности в Python.

    I/O-bound задача

    В задаче, где основное время уходит на ожидание сетевого ответа, все три подхода показали значительное ускорение по сравнению с гипотетическим последовательным выполнением.

    1. asyncio (3.70 с) оказался самым быстрым. Это объясняется его архитектурой: событийный цикл и кооперативная многозадачность позволяют переключаться между задачами с минимальными накладными расходами, не прибегая к созданию тяжеловесных потоков или процессов. Это идеальный инструмент для управления тысячами одновременных I/O-операций.

    2. threading (6.67 с) занял второе место. Он также очень эффективен для I/O-задач, так как GIL освобождается во время ожидания, позволяя другим потокам работать. Однако создание и управление потоками на уровне операционной системы вносят больше накладных расходов, чем управление задачами в asyncio.

    3. multiprocessing (7.63 с) оказался самым медленным из трех. Хотя он и позволяет выполнять запросы конкурентно, издержки на создание и межпроцессное взаимодействие (IPC) слишком высоки для такого типа задач. Этот подход избыточен, когда основной барьер — ожидание, а не вычисления.

    Вывод: для задач, связанных с вводом-выводом, asyncio является наиболее эффективным подходом, за ним следует threading. multiprocessing стоит использовать только в том случае, если обработка полученных данных сама по себе является CPU-bound задачей.
